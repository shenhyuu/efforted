## 2. 系统架构

```
┌─────────────────────────────────────────────┐
│                浏览器 (PC / 手机)             │
│  Vue3 SPA + PWA (Service Worker 离线缓存)     │
│  ┌──────────┬──────────┬───────────────┐    │
│  │ Check-in │ 计时器    │ 织痕布 Canvas  │    │
│  │ (离线队列)│(本地持久) │  (只增不减)    │    │
│  └──────────┴──────────┴───────────────┘    │
└──────────────────HTTPS──────────────────────┘
                   │ REST / JSON (JWT)
┌─────────────────────────────────────────────┐
│              Nginx (TLS 终止/静态资源/反代)    │
└──────────────────┬──────────────────────────┘
┌─────────────────FastAPI (Uvicorn)────────────┐
│ ┌──────────────────────────────────────────┐ │
│ │ api/   路由层（薄）                        │ │
│ │ services/  业务层（织痕逻辑/计时/胶囊/导出） │ │
│ │ models/    SQLAlchemy 模型                 │ │
│ │ schemas/   Pydantic DTO                    │ │
│ │ core/      配置/安全/依赖注入/文案库        │ │
│ └──────────────────────────────────────────┘ │
│              │ aiosqlite (WAL)                │
│         zhihen.db (单文件, 每日备份)           │
└──────────────────────────────────────────────┘
```

要点：
- **计时器逻辑在服务端**（防刷新/断电丢失），前端本地也留 last-known 状态用于快速渲染。
- 前端离线 Check-in 存 IndexedDB 队列，恢复网络后批量 POST，服务端以 `client_created_at` 为准落库。
- 单进程部署即可承载个人/小团队规模；SQLite WAL 保证读写并发。

## 5. 横切关注点

### 5.1 认证与账户

- **MVP 默认单账户模式**：首次访问引导设置一个密码（无用户名/邮箱注册，降低门槛与隐私暴露），签发 JWT（有效期 30 天，记住设备）。
- `SINGLE_USER_MODE=true` 时所有数据属于该唯一账户；多账户模式预留 `users` 表结构，接口不变。

### 5.2 时间与时区

- 有明确时间的记录统一存 **UTC ISO8601**；补录日期可以省略，省略时 `time_scope=past` 且 `occurred_at=NULL`，界面统一显示为「过去」，不推断具体日期。「时段（早上/下午/晚上/深夜）」是独立字段，不与时刻强绑。
- 前端按浏览器本地时区渲染。日期切分逻辑放前端聚合（服务端只返回原始时间戳）。

### 5.3 错误处理

- 统一错误体：`{"error": {"code": "TIMER_NOT_FOUND", "message": "..."}}`；HTTP 语义准确（401/403/404/422）。
- **文案红线同样适用于错误信息**：不得出现「失败」「错误：你…」等审判式措辞，用「没找到这段计时，可能它已经收好了」。

### 5.4 隐私与安全

- TLS 强制（Nginx 层，HTTP 301）。
- SQLite 文件权限 600；每日加密备份（可选 age/gpg）。
- 任何遥测/统计 SDK 一律不引入；日志不记录内容字段，只记元事件与错误码。

### 5.5 文案治理（工程化）

- 后端 `i18n/copywriting.toml` + 前端 `copy/zh-CN.ts` 集中全部文案。
- CI 运行 `scripts/copy_lint.py`：对全部文案运行禁用词/禁用符号正则（坚持|加油|别放弃|连续\d+天|失败|还差|! …），命中即构建失败。这是把产品公理写进工程。

### 5.6 数据删除

- 单条记录删除立即物理删除。全量清空请求进入 **48h** 可撤销宽限期；宽限期内数据保持原状，到期后由任务在单个事务中立即物理删除全部用户数据。灰烬模式 = 保留 records 行但清空 content/energy 字段。

## 6. 关键技术方案细节

### 6.1 弹性计时器（断电恢复）

- `timers` 表保存 `status(running|paused|closed)`、`accumulated_seconds`、`last_resume_at`。
- 恢复算法：`elapsed = accumulated + (now - last_resume_at if running else 0)`——服务端每次读取时实时计算，不依赖客户端心跳。
- 断点卡片由 `timer_segments`（每次开始/暂停区间）生成。

### 6.2 织痕布数据协议

`GET /api/v1/weave` 返回按天分组的线段描述：`[{date, segments: [{y位置, 颜色(能量档映射), 长度(当日记录条数)}]}]`。前端 Canvas 只做渲染，**不做任何统计计算**（防止「统计页」心智回归）。

### 6.3 余烬温度

`temperature = clamp(1 - days_since_last_record / 90, 0.15, 1)`——最低余温 0.15，永不为 0；只影响视觉透明度，不产生任何文案。

### 6.4 离线 Check-in 队列

- IndexedDB 存 `{client_created_at, energy, note}`，恢复网络后 `POST /checkins/batch`（幂等键 = client UUID）。
- 服务端唯一索引 `UNIQUE(user_id, client_uuid)` 保证幂等。
