# 织痕 · 数据库设计（SQLite3）

版本：v1.0 · 引擎：SQLite3，WAL 模式 · ORM：SQLAlchemy 2.0 (aiosqlite)

---

## 0. 结构性红线（先于一切表设计）

1. **任何表不得存在 `streak` / 连续天数 / 断签相关字段。**「断」这件事在系统里根本不存在。
2. **不存在「目标」「配额」「完成率」类字段。**
3. 单条删除立即物理删除；全量清空请求保留 48h 可撤销宽限期，到期后在单个事务中立即物理删除。
4. 明确时间统一使用 UTC ISO8601 文本；无日期补录使用 `time_scope='past'`，不伪造时间戳。

启动 pragma：

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
```

## 1. ER 总览

```
users 1───* records 1───0..1 record_details（同表即可，见下）
users 1───* timers 1───* timer_segments
users 1───* lamps
users 1───1 user_settings
records（kind=checkin/backfill/timer_close/ember）统一记录表
```

设计取向：**一张统一 `records` 表承接一切「痕迹」**（Check-in、补录、计时收束），避免「不同来源不同地位」——这正是「补录与实时记录同权」的工程表达。

## 2. 表结构

### 2.1 users

```sql
CREATE TABLE users (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    username      TEXT    UNIQUE NOT NULL,          -- 单账户模式固定为 'me'
    password_hash TEXT    NOT NULL,
    created_at    TEXT    NOT NULL,                 -- UTC ISO8601
    last_seen_at  TEXT                                -- 仅用于重启卡片/余烬，永不用于催促文案
);
```

### 2.2 records —— 核心：一切痕迹

```sql
CREATE TABLE records (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id          INTEGER NOT NULL REFERENCES users(id),
    client_uuid      TEXT,                          -- 离线幂等键
    kind             TEXT    NOT NULL CHECK (kind IN ('checkin','backfill','timer_close')),
    occurred_at      TEXT,                           -- 明确发生时间；无日期补录时为 NULL
    time_scope       TEXT    NOT NULL DEFAULT 'exact' CHECK (time_scope IN ('exact','past')),
    day_slot         TEXT    CHECK (day_slot IN ('morning','afternoon','evening','night') OR day_slot IS NULL),
    energy           TEXT    CHECK (energy IN ('low','mid','enough') OR energy IS NULL),  -- 永远可空
    content          TEXT,                          -- 可选一句话，灰烬模式清空此列
    duration_seconds INTEGER,                       -- 仅 timer_close 来源携带；查询时默认折叠
    timer_id         INTEGER REFERENCES timers(id),
    created_at       TEXT    NOT NULL,
    ash              INTEGER NOT NULL DEFAULT 0,    -- 1=灰烬模式清空内容后的壳
    CHECK ((time_scope='exact' AND occurred_at IS NOT NULL) OR
           (time_scope='past' AND occurred_at IS NULL))
);
CREATE UNIQUE INDEX idx_records_uuid ON records(user_id, client_uuid) WHERE client_uuid IS NOT NULL;
CREATE INDEX idx_records_time ON records(user_id, occurred_at);
CREATE INDEX idx_records_kind ON records(user_id, kind);
```

设计说明：
- `kind` 存在但**不用于 UI 区分呈现**（补录与实时记录视觉无差异），仅用于内部溯源。
- `energy` 三档枚举直译产品定义（low/mid/enough），是织痕配色唯一数据源。
- `day_slot` 是补录的粗粒度时段，避免「补录精确计时」的精算负担。
- 日期缺省的补录使用 `time_scope='past'`、`occurred_at=NULL`；界面只显示「过去」，不推算日期，也不制造虚假排序精度。
- 没有任何字段表达「未完成」——NULL 即「用户没说」，界面不显示「未标记」。

### 2.3 timers —— 弹性计时器（无失败态）

```sql
CREATE TABLE timers (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id            INTEGER NOT NULL REFERENCES users(id),
    status             TEXT    NOT NULL CHECK (status IN ('running','paused','closed')),
    accumulated_seconds INTEGER NOT NULL DEFAULT 0,  -- 已累积（暂停前的全部）
    last_resumed_at    TEXT,                         -- running 时的最近恢复点
    created_at         TEXT    NOT NULL,
    closed_at          TEXT
);
CREATE INDEX idx_timers_user ON timers(user_id, status);
```

- 有效时长计算（纯查询推导，非存储字段）：
  `accumulated_seconds + (status='running' ? now - last_resumed_at : 0)`
- **无「放弃/失败/超时」状态**；关闭即收束为一条 `records(kind='timer_close')`，无关闭原因字段（关闭不需要理由）。

### 2.4 timer_segments —— 断点卡片的数据

```sql
CREATE TABLE timer_segments (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    timer_id   INTEGER NOT NULL REFERENCES timers(id),
    started_at TEXT NOT NULL,
    ended_at   TEXT,               -- NULL = 当前进行中的段
    reason     TEXT                -- 仅 'pause'，无失败语义；可选
);
CREATE INDEX idx_seg_timer ON timer_segments(timer_id);
```

断点卡片文案来源：取最近一个已结束段，计算其持续分钟数 →「你在这里停下了，那时你已经走了 N 分钟」。

### 2.5 lamps —— 留一盏灯

```sql
CREATE TABLE lamps (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id      INTEGER NOT NULL REFERENCES users(id),
    message      TEXT    NOT NULL,
    energy_at_write TEXT CHECK (energy_at_write IN ('low','mid','enough') OR energy_at_write IS NULL),
    created_at   TEXT    NOT NULL,
    opened_at    TEXT                -- 用户主动打开时刻；只记录，永不触发推送
);
```

- **没有 `due_date`/`push_at` 字段**——灯只被打开，不被投递，这是公理 A3 的结构表达。
- 打开时展示原话 + `energy_at_write` 语境。

### 2.6 user_settings

```sql
CREATE TABLE user_settings (
    user_id             INTEGER PRIMARY KEY REFERENCES users(id),
    low_energy_mode     INTEGER NOT NULL DEFAULT 0,   -- 低能量模式（手动开关）
    hide_all_numbers    INTEGER NOT NULL DEFAULT 0,   -- 隐藏所有统计数字
    nothing_mode        INTEGER NOT NULL DEFAULT 0,   -- 「什么都不做模式」：无提示无总结
    notify_enabled      INTEGER NOT NULL DEFAULT 0,   -- 推送默认关闭
    weekly_report_opt_out INTEGER NOT NULL DEFAULT 0, -- 「我不想被总结」永久选项
    privacy_mode        INTEGER NOT NULL DEFAULT 0,   -- 通知/标题去敏感词
    updated_at          TEXT NOT NULL
);
```

### 2.7 comeback_stats —— 重启次数（唯一「累计型」计数）

```sql
CREATE TABLE comeback_stats (
    user_id        INTEGER PRIMARY KEY REFERENCES users(id),
    total_presence INTEGER NOT NULL DEFAULT 0,   -- 累计「出现过的次数」，只增不减
    restart_count  INTEGER NOT NULL DEFAULT 0,   -- 重启次数（长空白后回来），被温柔看见的事实
    last_gap_days  INTEGER                       -- 最近一次空白天数，仅用于重启卡片文案
);
```

> 这是全库**唯一**计数表，且语义上「只增、永不归零」——streak 的反面。

### 2.8 export_jobs（P1 可选，异步导出）

```sql
CREATE TABLE export_jobs (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id    INTEGER NOT NULL REFERENCES users(id),
    format     TEXT NOT NULL CHECK (format IN ('json','png')),
    status     TEXT NOT NULL CHECK (status IN ('pending','done')),
    file_path  TEXT,
    created_at TEXT NOT NULL,
    expires_at TEXT NOT NULL     -- 导出文件 48h 后自动删除
);
```

### 2.9 purge_requests —— 全量清空宽限期

```sql
CREATE TABLE purge_requests (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id     INTEGER NOT NULL UNIQUE REFERENCES users(id),
    requested_at TEXT NOT NULL,
    execute_at   TEXT NOT NULL,       -- requested_at + 48h
    status       TEXT NOT NULL CHECK (status IN ('pending','cancelled'))
);
```

- 宽限期内不修改业务数据，用户可撤销请求。
- 到达 `execute_at` 后，在一个事务中物理删除该用户全部业务数据与清空请求；不保留软删行或可恢复副本。

## 3. 关键查询

```sql
-- 织痕布数据（明确日期一天一根线；无日期补录单独聚合为「过去」）
SELECT substr(occurred_at,1,10) AS day, energy, count(*) AS n
FROM records
WHERE user_id=? AND time_scope='exact'
GROUP BY day, energy ORDER BY day;

SELECT 'past' AS time_scope, energy, count(*) AS n
FROM records WHERE user_id=? AND time_scope='past'
GROUP BY energy;

-- 余烬温度（服务层计算，不入库）
-- temperature = clamp(1 - days_since(last record)/90, 0.15, 1)

-- 重启卡片素材
SELECT restart_count, last_gap_days, total_presence FROM comeback_stats WHERE user_id=?;
SELECT occurred_at, content FROM records WHERE user_id=? AND ash=0 AND time_scope='exact'
ORDER BY occurred_at DESC LIMIT 1;
```

## 5. 容量评估

个人使用 5 年：每天 10 条记录 ≈ 1.8 万行 + 内容文本，SQLite 单表千万行级才遇性能边界，完全无压力。织痕布查询走 `idx_records_time`，P95 < 10ms。
